## LogKV 参照実装

移植元 commit は `02abb4f803ca85db5a01a17acc3394e8b44f8bb2`
（Group LogKV training attention to share KV across queries）。
コピーしたファイルと SHA-256 は `UPSTREAM.json`。Attention コアは無改変、
移植元の2つのテストファイルは import パスのみ変更した。MIT LICENSE も保持する。

- 各レベルの最大 C−1 スロットが過去を重複なく分割する。
- 圧縮はチャンク末尾 Q を使う Attention pooling。Q は末尾を保持し、K/V を同じ重みで混合。
- 全レベルと self slot を1つの softmax で読む。
- `forward` は学習向け grouped QK/PV、`step` は任意長 prefill、`predict` は1トークン専用。
- 推論状態は `(levels, offset)`。各レベルの未完成部分のみ保持し、状態は対数サイズ。
- 元の新規訓練 CLI 標準は C=4、conv4、gate/self slot あり、phase/KV norm なし、固定減衰。
  低水準 `LogKV` コンストラクタの既定値とは異なる。

会話で導出した均等混合時の単層・先頭 value の係数（ゲート・出力射影前）:

- s=n−1, h=floor(log_C(s)), d_i=floor(s/C^i) mod C。
- 固定減衰あり: `C^(-2h) / (1 + sum_i d_i*C^(-i))`、概ね Θ(n^-2)。
- `no_level_bias`: `C^(-h) / (1 + sum_i d_i)`。
  桁数に比例してスロットが増える位置では Θ(1/(n log n))、s=C^m では Θ(1/n)。
- これは均等な圧縮・内容 logit を仮定した value 混合係数。学習済みモデルの
  因果的影響、勾配、残差や多層を含む記憶保持率ではない。

## 実装に向けた提案（未決定事項を含む）

1. Llama の embedding、FFN、RMSNorm、出力ヘッド、Q/K/V/O を流用する。
   初期は元モデルに合わせて追加 conv/gate のない移植用 Attention を作る。
2. 圧縮無効モードで元 Llama と出力・キャッシュの一致を確認する。
3. GQA の8 KVヘッドを32 Qヘッドへ展開する方式が初期実装候補。
   Q依存の圧縮結果はヘッドごとに異なるので、上位キャッシュまで8ヘッドで共有するには
   別の圧縮設計が必要。射影の重み共有と圧縮状態の共有を区別する。
4. 元の RoPE を Q/K に適用してから圧縮する案を評価する。
   要約へ RoPE を二重適用しない。位置情報の保持と長距離参照は実験で検証する。
5. 直近の非圧縮窓 + 古い区間の LogKV も比較候補。現在の C=4 は直近も早く圧縮する。
   窓と階層の重複・欠落がない参照範囲を定義してから実装する。
6. レベル固定減衰、ゼロ、学習可能係数、要約サイズ補正を比較候補とする。
   `no_level_bias` でも元 Attention と同じにはならない。同じ K の M個をまとめる特殊な
   場合には +log M が softmax の重み総量を保つが、一般の pooling の厳密な補正ではない。
7. 少数層の Attention 出力蒸留から始める。現行 Compressor はパラメータフリーなので、
   QKVO の LoRA 等または追加する圧縮パラメータを学習対象にする必要がある。
8. 置換層を増やし、全体の LoRA + 教師出力 KL / LM loss で適応する。
   日本語・推論・長距離参照・速度・メモリを別々に測る。

通常 Attention 層を残したハイブリッドは中間検証に有用だが、その層の KV cache は
依然として系列長に比例する。全モデルの対数キャッシュを達成したとは扱わない。
少数層の蒸留成功も、全32層で品質を保てることの保証ではない。
