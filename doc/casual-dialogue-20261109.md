# 雑談での反復観察（2026-11-09）

ユーザー依頼で、長期記憶の検査を外し、休日・食事・散歩・趣味などの雑談を続けた。
設定の取り違え、事実誤認、話題の逸脱では停止せず、同語・文・記号の反復を観察する。
11月8日の試行は952生成tokensで終わっていたため、反復耐性の改善を判断するには短かった。

**rank128は52ターン・16,773生成tokensまで継続した。以前の同一単語の数百回連続は
再現しなかったが、51ターン目（累計約1.5万生成tokens台）で空のコードブロックや
断片的な語句の持続的な反復が顕著になり、話題変更後の52ターン目でも再発したため停止した。**
rank32でも同じ雑談質問列では以前の即時の単語連打は再現せず、記号・書式の反復が先に出た。
この1組ではrank128の持続的な書式反復はより後だったが、rank増加による改善とは断定できない。

## 条件

- 主対象: `distill-20261108/step-0006719`、LoRA rank128 / alpha256。
- 比較対象: `distill-20261103/step-0006719`、LoRA rank32 / alpha64。
- 両方ともRoPEあり、CausalConvなし、C=4、BF16、RTX 3090。
- medium / temperature0.8 / top-p0.95 / seed20261105、1応答上限2,048 tokens。
- 各セッションでLogKV状態を保持し、analysisも引き継ぐ。途中の状態リセットなし。
- 目標100,000生成tokens、最大7.5時間。生成数はanalysis・EOSを含み、入力・終端補完は除く。
- 既存の `scripts/run_dialogue_experiment.py` とChatEngineを使用。ソースは `09fefcd`。
- 主対象GPU 1、比較対象GPU 2。同時使用は最大2 GPU。
- 相手役はCodex。初めは応答を読んで次の問いを書き、31ターン目以降は雑談の質問をまとめて
  キューへ追加して生成を監視した。外部LLM APIは使用していない。

同一token64連続、または128 tokens以上を占める4回以上の周期的反復（周期128以下）を
機械的な候補とし、実際の文面も読む。可変の空白・改行・番号を含む反復はこの検出を
すり抜けるので、記号だけの連続文字数と、空の箇条書き・見出しも追加で観察した。
これは追加の目視指標であり、事前に固定した統計的な合否基準ではない。

比較対象には主対象と同じ質問ファイルを渡した。ただし質問は主対象の応答を踏まえて
用意しており、両モデルの生成履歴は異なる。各checkpointにつき1軌跡であり、rankだけの
因果効果を測る比較ではない。11月5日の創作実験とは題材・応答上限も異なる。

## rank 128

| ターン | 観察 | 累計生成tokensの目安 |
|---|---|---:|
| 10 | 改行23連続。その後は文章へ戻る | 開始index 3,983 |
| 29 | `<\|channel\|>` 8連続。応答全体13 tokensでEOS終了 | 開始index 7,528 |
| 37 | 「アーチ」を短く繰り返した後に別の文章へ戻る | 10,321→10,678 |
| 44 | 改行41連続。その後は文章へ戻る | 開始index 12,922 |
| 45 | カードゲームの話に「魚の骨」「魚の形」「バナナの形」などの断片を反復。837 tokensでEOS終了し、次ターンは別の内容へ移る | 13,497→14,334 |
| 51 | 文房具の話に食べ物の断片と空のコードブロック・見出しを反復。1,638 tokensでEOS終了 | 14,706→16,344 |
| 52 | 日記の話でも空のコードブロック・箇条書きへ戻る。429 tokensで手動中断 | 16,344→16,773 |

indexは0始まり、矢印はターン前後の累計。51ターン目の生出力には「バナナ」が19回、
3連バッククォートの区切りが100回出現した。区切りの多くに実質的な内容がなく、
最長369文字が記号・空白のみ。次の52ターン目でも区切りが25回出現し、
終了時の末尾139文字が記号・空白のみだった。単純な語の出現数だけを停止理由にせず、
空の書式を並べ続ける文面と、別の話題への変更後にも再発したことを見て停止した。

全52ターンで同一tokenの最大連続は44ターン目の**改行41回**。
同一token64連続・128 tokens以上の厳密な周期反復という機械的な閾値は一度も超えていない。
空白や記号が少しずつ変化するため、これらの閾値だけなら今回の持続的な反復を検出できない。
「単語を数百回連打する現象は未観測」と「反復が起きなかった」は別の結論である。

入力2,154 / 生成16,773 / 終端補完25 / 状態累計18,952 tokens、約5,089秒（約85分、
相手役の確認・待機を含む）。51応答がEOS、最後の1応答が手動中断で、生成上限終了はなかった。
53〜70の用意済み質問は `deferred-prompts/` に保存し、実入力には含めていない。
元モデルの65,536 contextにも10万生成tokensにも未到達であり、その範囲の耐久性は未検証。

早期から話題の逸脱もあり、長く生成できたことを自然な雑談の維持とは解釈しない。
23ターンではHarmonyヘッダーなどが崩れ `parts=[]` になったが、生出力には文章を含む場合がある。
51ターン目の反復は解析上analysis側、52ターン目はfinal側にも出現している。

## rank 32での比較観察

14ターン目で崩れた表の記号が229文字連続したが、その後は文章に戻った。
22ターン目の言語・挨拶の話題では、空の見出しや番号の列から、`―` と改行の反復へ進んだ。
4-token周期の反復が253 tokens続く区間は、累計生成index **9,561**（0始まり）、
状態index **10,688**から始まる。その前にも空見出しの反復があり、この数値は反復全体の
最初ではなく、検出された最長の厳密な周期区間の開始位置である。
記号だけの最長連続は742文字。後半に文章へ戻るが、応答は2,048 tokensの上限で終了した。

次の23・24ターン目は別の話題で310 / 132 tokensを生成してEOS終了し、長い反復はなかった。
しかし25ターン目の外遊びの話では空の箇条書きが再発し、末尾363文字が記号・空白のみの
状態となったため、736 tokens生成した時点で手動中断した。これは同じ日本語の単語の
大量反復ではなく、記号・書式の反復として区別する。

25ターン、入力1,243 / 生成12,315 / 終端補完2 / 状態累計13,560 tokens。
約2,327秒（待機を含む）で状態保存後に終了。26〜40の質問ファイルは未使用。

同じ質問ファイル1〜25の一致は検査済み。ただし生成履歴・EOSの出る長さが異なるため、
生成数・ターン数だけの比率を「何倍改善」とは扱わない。
11月5日は創作で生成index1,072から「団」435連続が出たのに対し、今回のrank32の雑談では
その現象自体が再現していない。題材・対話の進め方の影響をrankの効果と混同しない。

## 終了と検査

両実験とも `control.cmd` の `save_and_exit` により `operator_stop` で終了。
全77ターンの入力を元tokenizerで復号し、実際の質問全文が含まれることを確認した。
出力IDsの復号と `raw`、入出力token数、ターン間のcache offset、累計と終端補完の計数が一致。
各3個の保存状態をCPUで読み戻し、全32層のoffsetと上位offsetの一致・CPU/CUDA RNGの存在・
終了状態と最終集計の一致を検査した。保存状態からの生成再実行は今回行っていない。

|---|---:|---:|
| rank128 | 4.5〜12.75 MiB | 約16.45 GiB |

runner例外・OOMによる終了ではない。GPU 1・2は解放済み。
